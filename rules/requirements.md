# wText 누적 요구사항

최종 정리: 2026-11-03. 이 문서는 새 작업을 시작할 때 `rules/rules.md`에 이어 읽는 사용자 요구사항의 기준 문서다.

기존 `docs/REQUIREMENTS.md`의 내용을 이관하고 [프로젝트 규칙](rules.md), [변경 이력](../CHANGELOG.md), [기능 안내](../docs/FEATURES.md) 및 이번 사용자 지시를 대조해 누락된 항목을 보완했다. 초기 요청은 Git 이력 `16a1ac2`의 설명용 원본에서 확인했다. 원본 파일은 로컬에만 보존하며 다시 추적하지 않는다.

아래 구현 방향과 수용 기준에는 사용자 요청을 구체화한 기술 결정이 포함된다. 버전별 기록은 당시 범위와 검증 결과이며, 현재 적용 범위는 뒤의 변경 결정을 함께 따른다. 최신 배포·검증 상태는 [배포 안내](../docs/RELEASING.md)에서 확인한다. 과거 대화에서 확인할 수 없는 요청을 추정해 추가하지 않는다.

## 제품 목표와 해석

Windows x64에서 사용할 수 있는 독립 실행 텍스트 편집기를 만든다. Sublime Text처럼 편집에 집중할 수 있는 탭 중심 화면과 Notepad++의 실용적인 파일 작업을 참고한다. 두 파일의 차이를 쉽게 확인하는 기능을 첫 버전의 필수 기능으로 둔다.

“주요 편집기의 장점을 모으기”는 범위가 넓으므로 첫 버전은 안정적인 편집·저장·검색·비교에 집중한다. 다른 제품의 전체 기능, 성능, 플러그인 호환성을 보장하는 요구로 해석하지 않는다.

## 확정된 변경 사항

1. 프로그램명은 **wText**로 사용한다. 사용자 요청에 따라 실행 파일과 설치·바로가기 이름을 통일한다.
2. InstallShield 제품 자체를 사용해야 하는 요구는 해제했다. 사용자가 “무료 도구로 Windows 설치 마법사 제작”을 선택했으며 NSIS를 채택했다.
3. 배포는 별도 런타임 설치가 필요하지 않은 self-contained 방식으로 한다. 용량이 늘어나는 대신 설치 후 바로 실행할 수 있다.

## 1.0.1 바탕화면 바로가기 — 2026-10-10

- 설치 마법사에서 바탕화면 바로가기 생성 여부를 선택한다. 첫 설치는 기본 선택하고 재설치·업그레이드에서는 이전 선택을 유지한다.
- 현재 사용자 바탕화면에 올바른 실행 대상·작업 폴더·앱 아이콘을 가진 바로가기를 만든다. 선택 해제 시 기존 바탕화면 바로가기를 제거하고 시작 메뉴 바로가기는 유지한다.
- 프로그램 제거 시 두 바로가기를 정리하며 사용자 추가 파일은 보존한다. 무인 설치의 `/DesktopShortcut=1`·`/DesktopShortcut=0`도 같은 선택을 적용한다.

## 1.0.2 상단 화면 정리 — 2026-10-10

- 중복된 열기·저장·찾기·Aa·파일 비교 버튼을 제거하고 기존 메뉴·단축키로 접근한다.
- 사이드바 토글·앱 아이콘·wText 이름을 파일 메뉴 왼쪽에 한 줄로 배치해 편집 공간을 확보한다. 집중 모드에서 복귀해도 메뉴 높이를 유지한다.
- 변경된 메뉴 사용법과 실제 화면을 문서에 반영한다.

비교창은 임시 작업용으로 닫으면 입력을 보관하지 않는다. 원본 파일은 변경하지 않는다. 파일 로딩은 모든 대상을 읽고 검증한 뒤 입력을 바꾸며, 비교 중 중복 입력 작업을 막는다. 회귀 검사는 실제 WPF 편집기·클립보드 붙여넣기·FileDrop 라우팅 이벤트를 사용한다. Windows 탐색기에서 실제 마우스로 끌어 놓는 조작은 별도 수동 검증 항목이다.

1.1.0 검증 결과: Release 빌드 경고·오류 없음, xUnit 90개 및 WPF 회귀 검사 통과. 1.0.2에서 업그레이드한 설치본에서도 같은 검사를 통과했고 바로가기 선택별 재설치·신규 설치·제거와 사용자 파일 보존을 확인했다.

## 1.1.1 비교 색상과 가독성 — 2026-10-11

- 수정 줄 배경을 더 진하게 하고 글자·줄 번호 대비를 확보한다. 변경된 단어는 한 단계 밝은 배경으로 구분한다.

## 1.2.1 소스별 들여쓰기 설정 — 2026-10-11

- 설정에 들여쓰기 탭을 두고 공통 기본값과 언어별 공백/탭·너비 1~8칸·기존 문서 감지 여부를 저장·복원한다. JSONC·Vue·SCSS·Less도 구분한다.
- 고정 4칸 정렬 대신 기존 문서 들여쓰기를 기본적으로 우선 감지한다. 감지를 끄면 지정값으로 통일하고, 새 문서나 모호한 입력은 설정값을 쓴다.
- 열린 문서의 Tab 입력에도 적용한다. 설정 변경만으로 본문·실행 취소 기록을 바꾸지 않으며 YAML에는 공백을 사용한다. 이전 설정 파일과 호환한다.

## 1.4.1 저장 확인 단축키 — 2026-10-13

- 종료·탭 닫기의 저장 확인창에서 Y는 저장 후 닫기, N은 원본 파일을 수정하지 않고 닫기, C/Esc는 변경 내용을 유지하고 계속 편집한다.
- 버튼에 Y/N/C를 표시하고 기존 Enter·Tab·창 X 동작을 유지한다. 키 반복 입력과 Ctrl/Alt/Windows 조합은 무시한다.
- 오류·인코딩 대화상자는 영향을 받지 않는다. 기본 작업 이어하기가 켜져 있을 때 창 종료 시 확인창 없이 복구본을 보관하는 동작도 유지한다.
- 단축키 결과와 실제 창 종료·파일 저장·미저장 버퍼 보존 검사를 추가했다. Windows 대상 컴파일만 통과했으며, 사용자 PC에서 기능 동작을 확인하고 1.4.1 공개를 요청했다. 자동 WPF 실행·새 화면·IME·설치 검증은 CI 중단에 따라 미실행 상태로 별도 기록한다.

## 1.4.2 새 문서 입력 포커스 — 2026-10-13

- Ctrl+N과 파일 → 새 문서 실행 후 새 탭의 첫 삽입 위치에 키보드 포커스를 주어 별도 클릭 없이 입력·Ctrl+V를 받는다.
- 검색창에 포커스가 있던 경우에도 새 편집기로 이동하며 기존 문서 내용은 유지한다. 예약된 포커스 이동 전에 다른 탭을 선택하면 그 탭의 포커스를 뺏지 않는다.
- WPF 회귀 검사에 단축키·메뉴 경로, 검색창·편집기 시작 위치, 입력·클립보드 붙여넣기와 탭 변경을 포함한다. Linux에서는 컴파일만 확인했다. 사용자 PC에서 기능 동작을 확인하고 1.4.2 공개를 요청했다. 자동 WPF·IME·설치 검증은 미실행으로 구분한다.

## 구조와 데이터 보호

- `WookText.Core`: UI와 무관한 파일 인코딩, 저장, 비교, 검색, 파일 작업과 설정 로직.
- `WookText.App`: 실제 AvalonEdit 컨트롤을 탭별로 유지하여 커서·실행 취소 상태를 보존한다. `Explorer/`는 화면·노드·작업 폴더 상태를 분리한다.
- 읽기: BOM을 우선 식별하고 나머지는 엄격한 UTF-8로 검사한다. 실패한 경우에만 사용자 확인 후 CP949로 읽는다. BOM 없는 UTF-16/32 자동 감지는 지원하지 않는다.
- 저장: 인코딩 가능 여부를 먼저 검사하고 같은 폴더의 임시 파일에 기록한 다음 원본을 교체한다. 저장 직전 해시로 이미 발생한 외부 변경을 확인한다. 네트워크 파일시스템의 동시 쓰기까지 잠그는 기능은 아니다.
- 개별 탭 닫기: 수정 문서는 저장·버리기·취소를 선택한다. 저장 취소나 실패 시 문서를 닫지 않는다. 창 종료는 기본적으로 작업을 보관하며, 이어하기를 끈 경우에만 저장 여부를 묻는다.
- 비교: 파일을 읽거나 직접 입력·붙여넣은 현재 텍스트를 UI 스레드 밖에서 계산한다. 결과는 정렬된 읽기 전용 화면이고 입력은 별도로 편집한다. 파일 원본에 저장하지 않으며, 줄바꿈 차이와 수정하지 않은 두 파일의 인코딩 차이를 별도로 알린다.
- 탐색: 폴더를 펼칠 때 읽고 외부 변경 시 기존 노드를 재사용한다. 생성·이름 변경은 기존 파일을 덮어쓰지 않으며 연결 폴더 안으로 자동 진입하지 않는다.
- 세션: UI에서 불변 문서 스냅샷을 잡고 백그라운드에서 원본 교체 방식으로 기록한다. 창마다 잠금을 갖고 최종 보관 실패 시 종료를 취소한다. 이전 복구본과 읽을 수 없는 원본을 보존한다.
- 설치: 전용 폴더와 설치 식별자를 확인한다. 제거 시 패키지 파일 목록만 삭제하고 사용자 추가 파일은 남긴다. 검증용 설치는 별도 레지스트리·바로가기 이름을 사용한다.
- 바탕화면 바로가기(1.0.1): 설치 중 체크박스로 생성 여부를 선택한다. 기본 선택과 이전 설정 복원, 선택 해제 시 기존 바로가기 제거, 프로그램 제거 시 정리를 지원한다. 현재 사용자 바탕화면을 사용하며 시작 메뉴 바로가기는 유지한다.

1.7.2까지 파일 크기 한도는 16 MiB였다. 2026-11-03 지시로 1.8.0 준비 소스에서 대용량 모드를 추가하며 상세 한도는 아래 새 요구사항을 따른다. 비교 한도는 한쪽당 500,000자·20,000줄이다. 탐색기는 폴더별 파일·하위 폴더 합계 10,000개까지 표시한다. 이름·경로 검색은 최대 100,000개 항목을 확인하여 결과 200개까지 제공하고 한도 도달을 안내한다. 대형 파일 전용 모드는 1.8.0의 확정 요청으로 변경했다. 무제한 규모의 프로젝트 탐색은 후속 범위다.

후속 후보는 임의 위치 다중 커서, 명령 팔레트, 심볼 이동, 코드 접기, 정규식·폴더 전체 파일 내용 검색, 비교 병합, 최근 파일 목록, 파일 이동·삭제이다. 확정된 구현 요청이나 현재 기능으로 표시하지 않는다. 미니맵·직사각형 블록·줄 편집은 1.6.0부터, 블록 선택 변환 단축키는 1.6.1부터 제공한다. 다양한 Windows 환경의 한글 IME, 접근성, 고해상도 배율과 전원 장애 상황은 추가 검증 대상이며 코드 서명과 자동 업데이트도 후속 범위다.

## PDF 도구 정리·기본 글꼴·다양한 미리보기 (1.7.1 준비) — 2026-11-02

- 사용자 요청: 원본 글꼴을 무시하는 기능, 버튼이 많은 상단 정리, Markdown 이외 HTML 등 다양한 작성 형식 미리보기.
- 확인한 선택: **수정한 글자만 기본 글꼴 사용**. 전체 PDF 표시 글꼴을 바꾸지 않는다. 기본 글꼴 사용을 기본값으로 켜고, 기존 글꼴 사용으로 전환할 수 있으며 선택을 재실행 후에도 유지한다. 수정 단위는 선택한 텍스트 개체 전체이고 나머지 개체·페이지를 변경하지 않는다.
- 확인한 선택: **레이아웃 미리보기면 충분**. Markdown·HTML·SVG·CSV/TSV·JSON·XML을 지원하며 JavaScript 실행은 범위에서 제외한다. HTML의 CSS 배치, SVG 이미지, 표 데이터와 구조화 문서 표시를 제공한다.
- PDF 상단은 페이지 이동·확대·찾기와 주석/편집/페이지 메뉴로 정리한다. 검색창은 요청 시 펼치고 기존 개체를 선택했을 때만 수정/삭제 버튼을 표시한다. 기존 기능·단축키를 유지한다.
- 문서 미리보기는 확장자 자동 감지와 수동 형식 선택, 미저장 내용 갱신, 켜짐·형식 세션 복원을 제공한다. 저장 전 문서는 언어 선택 또는 미리보기 형식 선택을 사용하며 기본 자동값은 Markdown이다. 문법 오류·한도 초과는 원문을 보존하고 안내한다.
- 1.7.0의 WPF Markdown 전용 렌더러를 1.7.1의 WebView2 기반 문서 미리보기로 변경한다. 고정 런타임을 포함해 별도 설치가 필요하지 않게 한다. 무료 사용·재배포 약관과 SDK 고지, 최초 실행 동의를 포함하며 런타임 자체는 프로젝트의 MIT 라이선스와 별도다.
- 외부 페이지 리소스·스크립트·하위 프레임은 로드하지 않는다. 문서 폴더 안의 상대 CSS·이미지·글꼴을 표시하고 링크는 사용자 클릭으로 기본 브라우저에서 연다. SVG는 정적 이미지로 표시한다. Vue/React 실행, 서버 템플릿 실행, OCR·문단 재배치는 추가 승인된 범위가 아니다.
- 수용 검증: 기존 글꼴에 없는 한글을 기본 글꼴로 교체·재열기, 다른 페이지 보존, 설정·세션 유지, CSV 따옴표/줄바꿈·HTML/CSS·JSON/XML 오류·상대 리소스 경계, 기본/최소 창의 PDF 도구 접근성. Linux Core, Windows 대상 컴파일, 실제 Windows WPF 실행·화면·설치는 구분한다. 현재 검증 결과와 패키지는 [배포 안내](../docs/RELEASING.md)에 기록한다.

## 로딩 종료·미리보기 종료·제거 잔여물·재설치 지연 수정 (1.7.2 준비) — 2026-11-02

- 사용자 신고: 이전 버전에서 PDF를 연 상태로 새 버전을 설치하면 ‘켜졌다가 로딩 중 꺼짐’. 제거 뒤 Programs에 남아 재설치가 실패하며 재설치에도 시간이 오래 걸린다. 미리보기를 켤 때 앱이 종료되는 현상도 함께 수정한다.
- PDF: 복원한 작업을 먼저 표시하고 네이티브 PDF 처리를 별도 프로세스로 격리한다. 비정상 종료·잘못된 응답·60초 초과·취소 시 해당 작업만 중단하고 원본과 보관 버퍼를 유지한다. 탭에서 실패 안내와 명시적 재시도를 제공하며 다른 문서는 계속 편집할 수 있어야 한다.
- 미리보기: 브라우저 생성·실패·정리 중 예외가 앱으로 전파되는 경로를 처리한다. 표준 WPF WebView2로 전환하고 브라우저 종료 후 원문/실행 취소 유지, 안내, 새로 고침 복구를 제공한다. 기존 정적 레이아웃 범위와 스크립트 비실행 조건을 유지한다.
- 설치·제거: 실행 중 앱/미리보기의 파일 잠금을 변경 전에 확인한다. 패키지 파일이 남았는데 제거가 성공한 것으로 등록/식별자를 없애지 않는다. 알려진 이전 파일만 정리하며 사용자 추가 파일과 설정/작업 복구본은 보존한다. 기본 Programs 폴더의 알려진 잔여물은 복구 설치할 수 있어야 한다.
- 재설치: 변경 없는 대형 런타임을 다시 풀고 쓰지 않도록 파일별 압축과 수정 시각 기준 건너뛰기를 적용한다. 자체 런타임 포함 정책은 유지하며 다운로드 용량 감소나 특정 설치 시간을 보장하지 않는다.
- 진단: 예기치 않은 관리 코드 종료는 `%LocalAppData%\wText\logs\startup-errors.log`에 버전·예외를 남긴다. 모든 네이티브/OS 종료를 이 로그로 포착할 수 있는 것은 아니다.
- 수용 검증: 자식 프로세스 종료/잘못된 응답/시간 초과/취소 후 부모와 버퍼 유지, 손상 PDF 혼합 세션 복구, 미리보기 프로세스 종료 후 재시작, 잠긴 DLL에서 부분 제거 방지, 사용자 파일 보존, Programs 잔여물 복구, 변경 없는 런타임 쓰기 생략. 사용자 PC 오류 로그와 실제 Windows 실행 없이 신고 원인을 확정하거나 해결 검증이 끝났다고 표시하지 않는다. 검증 상태는 [배포 안내](../docs/RELEASING.md)를 따른다.

## 대용량 로그 로딩과 메모리 사용 개선 (1.8.0 준비) — 2026-11-03

- 사용자 신고: 약 100MB 로그 등 bulk data를 열면 자원을 과도하게 사용하다 종료되는 현상이 반복된다. 해당 크기를 처리하도록 점검·수정하고 미리보기 등 메모리 부담이 큰 기능을 비활성화한다. 사용자 원본 파일과 Windows 메모리 덤프는 제공되지 않았으므로 특정 종료 원인을 확정하지 않는다.
- 조사: 기존 파일 API는 16 MiB 제한과 전체 바이트/문자열 할당을 사용했다. 편집 후 분석·들여쓰기·검색·미리보기·저장·세션 보관에도 전체 본문 접근이 있었다. 따라서 한도 확대와 별도로 반복 복사·렌더링·자동 보관 비용을 줄인다.
- 승인된 구현 범위: 파일 열기/저장 최대 256 MiB, 열기 시 본문 134,217,728자·2,000,000줄·한 줄 100,000자. 창 합계 268,435,456자·4,000,000줄(다시 불러오기 중 이전 버퍼 포함). 한도를 넘는 파일은 구체적인 안내와 함께 기존 탭을 보존한다. PDF 32 MiB 및 비교 500,000자·20,000줄 한도는 유지한다.
- 자동 대용량 모드: 파일 16 MiB 이상, 본문 8,388,608자 이상 또는 100,000줄 이상. 파일 읽기·디코딩·해시·편집 버퍼와 행 구성은 작업 스레드에서 청크 처리한다. 완료된 버퍼만 UI에 연결하고 인코딩 실패/취소 때 부분 문서를 적용하지 않는다. 저장은 스냅샷 reader로 처리하며 엄격한 인코딩·원본 교체·외부 변경 충돌 차단을 유지한다.
- 제한 기능: 미리보기·미니맵·구문 강조·자동 줄바꿈·공백 표시·들여쓰기 자동 감지·입력 후 전체 줄바꿈 분석·전체 검색 강조/개수·모두 바꾸기·검색 결과 동시 편집·자동 정렬. 설정 변경으로 제한이 풀리지 않는다. 실행 취소는 최대 100개 그룹이며, 문서 크기를 줄여도 다시 불러오기 전까지 대용량 모드를 유지한다.
- 유지 기능: 일반 편집·저장/다른 이름으로 저장·개별 바꾸기·F3/Shift+F3 이전/다음 검색과 순환. 대용량 검색은 65,536자 이하 검색어를 작은 청크로 찾고 본문/탭/검색 조건 변경·닫기 시 오래된 결과를 취소한다.
- 보관 변경: 일반 문서의 자동 복구는 유지한다. 대용량 본문은 자동 보관하지 않으며 경로와 표시 위치만 형식 3에 저장한다. 화면 안내와 함께 수정된 대용량 문서의 창 종료에도 저장/버리기/취소를 적용한다. 파일 없는 대용량 새 문서도 저장 확인 대상이다. 강제 종료 시 미저장 대용량 변경은 복구되지 않는다. 원본이 없을 때 빈 문서로 복원하지 않는다.
- 외부 갱신 변경: 대용량 로그의 주기적 전체 해시 검사·자동 다시 불러오기를 중지한다. 파일 → 다시 불러오기로 반영하며 저장 시 해시 충돌 확인은 계속 적용한다.
- 수용 검증: 실제 생성한 100 MiB 로그 읽기/저장 해시 일치, 디코더·CRLF·서로게이트 청크 경계, 크기/행/긴 줄 제한, 취소·저장 실패 시 원본 보존, 청크 검색 경계와 순환, 작은 미저장 문서와 대용량 경로의 혼합 세션. Windows 검사는 로딩 중 UI heartbeat·제한 기능·설정 변경·검색·저장/취소/버리기·재실행·화면을 포함한다.
- 구현/검증/패키지 상태는 [배포 안내](../docs/RELEASING.md)에 기록한다. 공개 다운로드는 1.7.2를 유지하며 실제 Windows 100MB 로딩·메모리 및 사용자 파일 재현 검증을 완료한 것으로 표시하지 않는다. CI 재개·공개 릴리스는 요청되지 않았다.

## 대용량 파일 스크롤 보정 (1.8.1 준비) — 2026-11-03

- 사용자 추가 신고: 내용이 많은 벌크 파일을 아래로 내려볼 때 버벅임이 크므로 스크롤을 더 보정한다. 앞서 준비한 1.8.0의 로딩·메모리 보호 범위를 유지한다.

- 동작 변경: 대용량 스크롤바 손잡이를 끄는 동안 본문은 유지하고 놓은 위치에서 갱신한다. 안내 툴팁·설명서에 표시한다. 설정 변경과 편집 중 대용량 전환에도 적용하고 작은 파일로 다시 불러오면 기본 동작으로 돌아간다.

## Ctrl+G 줄 이동과 새 버전 공개 요청 (1.8.2) — 2026-11-03

- 사용자가 대용량 스크롤 문제가 “어느 정도 해소된 것 같다”고 확인하고 Ctrl+G 특정 줄 이동 등의 편의 기능을 추가한 뒤 커밋·푸시·새 버전 릴리스를 명시적으로 요청했다. 앞선 미공개 유지 결정을 이번 배포에 대해 변경한다. 임의의 후속 후보 전체를 승인한 것으로 확대하지 않는다.
- 줄 이동: Ctrl+G와 편집 메뉴에서 현재 줄·열/전체 줄 수를 보여 주고 줄 번호 또는 줄:열 입력을 받는다. 1부터 시작하며 열을 생략하면 첫 위치로 이동한다. 빈 문서·끝의 빈 줄·CR/LF/CRLF·자동 줄바꿈에 같은 원문 줄 기준을 적용한다. 열은 상태 표시줄 Col 기준이며 탭은 한 문자로 센다.
- 오류/취소: 숫자 형식·범위·입력 길이를 검사하고 원래 위치를 보존한 채 같은 창에 오류를 표시한다. Enter/이동은 선택을 해제하고 대상에 커서·화면·입력 포커스를 옮긴다. Esc·취소·X는 이동하지 않는다. PDF에서는 명령을 비활성화한다.
- 대용량: 전체 본문 복사/분할 없이 행 인덱스로 대상만 조회한다. 본문·실행 취소·미저장 상태를 유지하고 대기 중 검색/휠 이동을 취소해 새 위치가 되돌아가지 않게 한다. 검색 결과 동시 편집도 종료한다.
- 수용 검증: Core 입력/경계/범위/200만 줄 단일 조회, WPF Ctrl+G·메뉴·찾기 입력 중 호출·오류/취소·빈/자동 줄바꿈 문서·실행 취소·100 MiB 끝 이동·PDF 비활성화와 실제 화면 생성 검사를 준비한다. Linux 실행·Windows 대상 컴파일·실제 Windows 실행을 구분한다.
- 배포: 미공개 1.8.0/1.8.1의 대용량 로딩·메모리/스크롤 개선을 포함해 1.8.2로 커밋·푸시·태그/공개 릴리스를 만든다. 확정 커밋에서 설치 EXE·무설치 ZIP·SHA-256을 생성하고 업로드 파일을 다시 내려받아 대조한다. 게시 후 README 다운로드·기능/배포 기록을 동기화한다. 자동 Windows WPF·IME·DPI·화면·설치 검증 미실행과 CI 중단을 명시한다.
