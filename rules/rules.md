# wText 프로젝트 규칙

## 제품 및 배포

- 프로그램명은 **wText**로 통일한다. 실행 파일은 `wText.exe`로 만든다. 저장소명과 내부 네임스페이스 `WookText`는 유지한다.
- Windows x64를 대상으로 개발한다. 설명용 원본 `resources/settings.txt`는 로컬에만 보존하며 Git에 올리지 않는다. `resources/setting.txt`도 같은 방식으로 제외한다.
- 2026-10-09 사용자 결정에 따라 InstallShield 대신 무료 도구로 설치 마법사를 제작한다. 첫 버전은 NSIS를 사용한다.
- 프로젝트의 자체 코드는 MIT로 배포하고, 의존성의 라이선스 및 저작권 고지를 설치 파일과 함께 제공한다.
- 설치는 현재 사용자 범위로 제공하며, 기존 파일 연결을 임의로 변경하지 않는다.
- 설치 마법사에서 바탕화면 바로가기 생성 여부를 선택하고 재설치·업그레이드에 선택을 유지한다. 제거 시 설치한 바로가기도 정리하며 검증용 설치는 별도 바로가기 이름을 사용한다.

## 개발과 검증

- **사용자 편의를 최우선으로 한다.** 자주 쓰는 동작은 메뉴와 단축키로 제공하고, 설정과 작업 공간 상태를 유지하며, 숨긴 UI를 쉽게 다시 표시할 수 있게 한다. 단순히 동작하는 수준을 넘어 실제 편집 흐름을 검증한다.
- 탐색기는 키보드 이동·파일 검색·생성·이름 변경·자동 갱신을 제공한다. 목록·검색은 UI를 막지 않도록 처리하고 작업 위치·펼침을 유지한다. 파일 작업은 열린 문서의 편집 상태를 보존하며 기존 파일을 덮어쓰지 않는다. 연결 폴더를 자동 순회하지 않고 한도·접근 오류를 안내한다.
- 1.0.0부터 작업 폴더는 최대 10개를 동시에 지원한다. 폴더별 접기·닫기·순서 변경, 전체 닫기와 최근 10개 다시 열기를 제공한다. 닫기는 파일을 삭제하거나 문서 탭을 닫지 않는다. 목록·순서·펼침을 복원하고 이전 단일 폴더 설정을 옮긴다.
- 앱의 저장 확인·인코딩 확인·오류 알림은 공통 테마 대화상자를 사용한다. ‘저장 / 저장 안 함 / 계속 편집’처럼 동작을 명시하고 대상 문서와 경로를 표시한다. Esc·X는 취소로 처리하며 오류 상세는 펼쳐 읽거나 복사할 수 있게 한다.
- 기본 테마는 wShell을 참고한 블랙·오렌지로 한다. wText 전용 문서 아이콘으로 작업표시줄에서 제품을 구분한다. 메뉴에 불필요한 테두리를 두르지 않는다.
- 기본 편집 글꼴은 영문·숫자 JetBrains Mono, 한글 Noto Sans KR로 한다. 글꼴을 배포본에 포함하고 OFL 고지를 유지한다. 글꼴·크기 변경은 미리보기와 저장을 지원한다.
- 도움말에는 제작자 Hyunwook Park와 GitHub `https://github.com/parkhw328/wook-text`를 표시한다.
- .NET 10 LTS, C#, WPF를 사용한다. 파일 처리와 비교 로직은 `WookText.Core`에 두어 UI와 분리한다.
- C#은 공백 4칸, 파일 범위 네임스페이스, 타입·메서드·속성 PascalCase, 매개변수 camelCase, 비공개 필드 `_camelCase`를 사용한다.
- 편집 시 인코딩과 줄바꿈을 보존한다. 저장 전 전체 인코딩을 검증하고, 외부 변경이 감지되면 덮어쓰기를 중단한다.
- 창 종료는 기본적으로 탭·미저장 버퍼를 LocalAppData에 보관하고 재실행 시 복원한다. 원본 파일 저장과 복구본 보관을 구분하고, 보관 실패 시 창을 닫지 않는다. 개별 탭에서 명시적으로 버린 문서는 복원하지 않는다.
- 작업 보관은 UI 밖에서 원본 교체 방식으로 기록하며 여러 프로세스가 같은 세션을 덮어쓰지 않도록 한다. 종료 이벤트가 끝나기 전 `Close()`를 재호출하지 않는다.
- 도움말에서 자체 MIT와 포함된 구성요소의 라이선스 원문을 읽을 수 있게 한다. README 사용 설명에는 예제 데이터로 만든 실제 화면을 포함하고 제품 변경 시 함께 갱신한다.
- 오류나 지원 범위를 벗어난 입력을 사용자에게 설명한다. 파일 내용을 조용히 손상시키는 대체 문자 변환은 금지한다.
- 테스트명은 `Method_Condition_ExpectedResult`로 작성한다. 파일 저장·인코딩·비교 변경에는 회귀 테스트를 포함한다.
- 사용자에게 전달하는 기능·UI 변경은 커밋·푸시만으로 마무리하지 않고 새 버전 번호, 변경 이력, README·화면, 배포 패키지와 체크섬을 함께 준비한다. 공개 릴리스 전에는 기존 다운로드 링크를 유지하고 준비 버전을 구분해 안내한다.
- 매 버전 변경 내용을 `CHANGELOG.md`에 기록한다. 배포 전 Release 빌드, 자동 테스트, WPF 화면 검증 및 설치·제거 검증을 수행한다.
- `AGENTS.md`와 요구사항 원본은 명시적인 수정 요청 없이 변경하지 않는다.
