# wText 프로젝트 규칙

## 새 작업 시작과 요구사항 기록

- 새로운 작업지시를 받을 때마다 구현 조사·계획·파일 수정·명령 실행에 앞서 `rules/rules.md`를 읽고, 이어서 `rules/requirements.md`를 읽는다. 이전 작업에서 읽었더라도 새 작업에서는 두 문서의 최신 내용을 다시 확인한다.
- `rules/rules.md`는 작업 방식과 공통 규칙, `rules/requirements.md`는 사용자 요구사항·수용 기준·변경 결정·후속 범위의 기준 문서로 관리한다. `docs/REQUIREMENTS.md`는 새 위치를 안내하는 링크만 유지한다.
- 새 요구사항이나 변경 지시는 같은 작업에서 `rules/requirements.md`에 누적 기록한다. 새 공통 규칙은 이 파일에 반영한다. 날짜와 요청 내용, 수용 기준을 확인 가능한 범위에서 적고, 구현 완료와 실제 검증 완료를 구분한다.
- 최신 사용자 지시로 기존 결정이 바뀌면 변경 전후와 근거를 남기고 현재 적용 기준을 명시한다. 제안·후속 후보를 확정된 요청이나 구현된 기능으로 표시하지 않는다.

## 제품 및 배포

- 프로그램명은 **wText**로 통일한다. 실행 파일은 `wText.exe`로 만든다. 저장소명과 내부 네임스페이스 `WookText`는 유지한다.
- Windows x64를 대상으로 개발한다. 설명용 원본 `resources/settings.txt`는 로컬에만 보존하며 Git에 올리지 않는다. `resources/setting.txt`도 같은 방식으로 제외한다.
- 2026-10-09 사용자 결정에 따라 InstallShield 대신 무료 도구로 설치 마법사를 제작한다. 첫 버전은 NSIS를 사용한다.
- 프로젝트의 자체 코드는 MIT로 배포하고, 의존성의 라이선스 및 저작권 고지를 설치 파일과 함께 제공한다.
- 설치는 현재 사용자 범위로 제공하며, 기존 파일 연결을 임의로 변경하지 않는다.
- 설치 마법사에서 바탕화면 바로가기 생성 여부를 선택하고 재설치·업그레이드에 선택을 유지한다. 제거 시 설치한 바로가기도 정리하며 검증용 설치는 별도 바로가기 이름을 사용한다.

## 개발과 검증

- **사용자 편의를 최우선으로 한다.** 자주 쓰는 동작은 메뉴와 단축키로 제공하고, 설정과 작업 공간 상태를 유지하며, 숨긴 UI를 쉽게 다시 표시할 수 있게 한다. 단순히 동작하는 수준을 넘어 실제 편집 흐름을 검증한다.
- 탐색기는 키보드 이동·파일 검색·생성·이름 변경·자동 갱신을 제공한다. 목록·검색은 UI를 막지 않도록 처리하고 작업 위치·펼침을 유지한다. 파일 작업은 열린 문서의 편집 상태를 보존하며 기존 파일을 덮어쓰지 않는다. 연결 폴더를 자동 순회하지 않고 한도·접근 오류를 안내한다.
- 1.0.0부터 작업 폴더는 최대 10개를 동시에 지원한다. 폴더별 접기·닫기·순서 변경, 전체 닫기와 최근 10개 다시 열기를 제공한다. 닫기는 파일을 삭제하거나 문서 탭을 닫지 않는다. 목록·순서·펼침을 복원하고 이전 단일 폴더 설정을 옮긴다.
- 앱의 저장 확인·인코딩 확인·오류 알림은 공통 테마 대화상자를 사용한다. ‘저장 / 저장 안 함 / 계속 편집’처럼 동작을 명시하고 대상 문서와 경로를 표시한다. Esc·X는 취소로 처리하며 오류 상세는 펼쳐 읽거나 복사할 수 있게 한다.
- 기본 테마는 wShell을 참고한 블랙·오렌지로 한다. wText 전용 문서 아이콘으로 작업표시줄에서 제품을 구분한다. 메뉴에 불필요한 테두리를 두르지 않는다.
- 기본 편집 글꼴은 영문·숫자 JetBrains Mono, 한글 Noto Sans KR로 한다. 글꼴을 배포본에 포함하고 OFL 고지를 유지한다. 글꼴·크기 변경은 미리보기와 저장을 지원한다.
- 도움말에는 제작자 Hyunwook Park와 GitHub `https://github.com/parkhw328/wook-text`를 표시한다.
- .NET 10 LTS, C#, WPF를 사용한다. 파일 처리와 비교 로직은 `WookText.Core`에 두어 UI와 분리한다.
- C#은 공백 4칸, 파일 범위 네임스페이스, 타입·메서드·속성 PascalCase, 매개변수 camelCase, 비공개 필드 `_camelCase`를 사용한다.
- 편집 시 인코딩과 줄바꿈을 보존한다. 저장 전 전체 인코딩을 검증하고, 외부 변경이 감지되면 덮어쓰기를 중단한다.
- 창 종료는 기본적으로 탭·미저장 버퍼를 LocalAppData에 보관하고 재실행 시 복원한다. 원본 파일 저장과 복구본 보관을 구분하고, 보관 실패 시 창을 닫지 않는다. 개별 탭에서 명시적으로 버린 문서는 복원하지 않는다.
- 작업 보관은 UI 밖에서 원본 교체 방식으로 기록하며 여러 프로세스가 같은 세션을 덮어쓰지 않도록 한다. 종료 이벤트가 끝나기 전 `Close()`를 재호출하지 않는다.
- 도움말에서 자체 MIT와 포함된 구성요소의 라이선스 원문을 읽을 수 있게 한다. README는 프로젝트 소개·다운로드·문서 링크와 기본 개발 명령 중심으로 간결하게 유지한다. 기능 설명과 예제 데이터로 만든 실제 화면은 `docs/FEATURES.md`, 상세 개발 안내는 `docs/DEVELOPMENT.md`에 두고 제품 변경 시 함께 갱신한다.
- 오류나 지원 범위를 벗어난 입력을 사용자에게 설명한다. 파일 내용을 조용히 손상시키는 대체 문자 변환은 금지한다.
- 테스트명은 `Method_Condition_ExpectedResult`로 작성한다. 파일 저장·인코딩·비교 변경에는 회귀 테스트를 포함한다.
- 사용자에게 전달하는 기능·UI 변경은 커밋·푸시만으로 마무리하지 않고 새 버전 번호, 변경 이력, README·화면, 배포 패키지와 체크섬을 함께 준비한다. 공개 릴리스 전에는 기존 다운로드 링크를 유지하고 준비 버전을 구분해 안내한다.
- 도움말 메뉴와 F1에 오프라인 기능 설명서를 제공한다. `docs/USER-GUIDE.md`를 앱에 내장하고 기능·단축키·한도·오류 대응을 변경할 때 함께 갱신한다. 목차·제목/본문 검색과 반복 열기·닫기 동작을 검증한다.
- 매 버전 변경 내용을 `CHANGELOG.md`에 기록한다. 배포 전 Release 빌드, 자동 테스트, WPF 화면 검증 및 설치·제거 검증을 수행한다.
- `AGENTS.md`와 로컬 설명용 원본(`resources/settings.txt`, `resources/setting.txt`)은 명시적인 수정 요청 없이 변경하지 않는다. 누적 요구사항 문서 `rules/requirements.md`는 위 기록 규칙에 따라 갱신한다.

## 환경 공통 작업 마무리

- Windows·Linux·원격 환경에서 같은 완료 기준을 적용한다. 기능 구현이나 패키지 생성만으로 완료를 보고하지 않고 아래 문서를 함께 대조한다. 상세 절차와 현재 상태는 `docs/RELEASING.md`를 따른다.
- README 소개와 `docs/FEATURES.md`의 사용법·단축키·화면 설명, `Directory.Build.props`, CHANGELOG, `rules/requirements.md`의 해당 기능, GitHub 릴리스 설명과 첨부 파일을 일치시킨다. 소스/패키지 버전과 공개 배포 버전은 구분한다.
- 화면 변경은 실제 WPF 실행에서 생성한 화면을 확인하고 `docs/FEATURES.md`에 반영한다. Linux에서 WPF를 실행할 수 없다면 확인된 Windows 결과를 사용하고 출처·버전을 기록한다. 화면을 새로 검증한 것처럼 쓰지 않는다.
- Linux라는 이유로 문서·규칙·릴리스 설명·체크섬 검증을 생략하지 않는다. Windows 실행, 교차 컴파일, 설치 실행 결과는 구분해 기록한다. 미실행 항목은 이유와 남은 작업을 명시한다.
- 사용자가 CI 생략·중단을 요청하면 재개 지시 전까지 실행하거나 재시도하지 않는다. 이는 문서와 로컬에서 가능한 검증까지 생략하라는 뜻이 아니다.
- 패키지에 포함되는 CHANGELOG·라이선스·소스가 바뀌면 다시 패키징하고 ZIP 내용, 체크섬과 릴리스 첨부 파일을 재검증한다. 업로드한 바이너리의 빌드 커밋을 기록한다.
- 공개 전에는 기존 공개 다운로드 링크를 유지하고 초안의 접근 범위를 표시한다. 공개 요청이 있어 게시했다면 README 다운로드·소개와 릴리스 상태를 같은 작업에서 갱신한다.
- 완료 보고에는 문서·화면·패키지·커밋/푸시 상태와 미검증 항목을 포함한다. 임시 경로만 남기지 말고 후속 작업자가 저장소에서 상태와 절차를 확인할 수 있게 한다.


## PDF·미리보기 처리 (1.7.0~1.7.1 준비)

- PDF는 텍스트 파일 경로와 분리하고 원본 바이트의 복사본에 편집을 적용한다. 직렬화·재열기 검증 후에만 변경 상태를 반영하며, 저장은 원본 해시 확인과 임시 파일 교체를 따른다.
- PDFium 접근은 프로세스 전역 잠금으로 직렬화하고 네이티브 핸들을 호출 범위에서 해제한다. 엔진 버전·패키지 잠금·배포 DLL·포함 구성요소 고지를 함께 갱신한다.
- PDF가 포함된 세션은 형식 2로 기록해 이전 앱이 PDF를 빈 텍스트로 복원하지 못하게 한다. 현재 앱은 형식 1도 읽는다. 복원 실패한 PDF 바이트를 빈 문서로 바꿔 덮어쓰지 않는다.
- 1.7.0에서는 Markdown을 WPF 문서로 표시했다. 2026-11-02 사용자 추가 요청에 따라 1.7.1부터 문서 미리보기로 확장하고 HTML/CSS 레이아웃은 앱에 포함된 WebView2 Fixed Version으로 렌더링한다. Markdown 원시 HTML과 모든 문서의 JavaScript 실행은 허용하지 않는다.
- PDF 원본 글꼴 무시는 기본적으로 켜고 수정한 텍스트 개체에만 Noto Sans KR을 적용한다. 나머지 개체·페이지는 유지한다. 사용자의 선택은 설정에 저장하며 지원하지 않는 문자를 조용히 대체하지 않는다.
- PDF의 기본 도구줄은 페이지 이동·확대·찾기와 주석/편집/페이지 메뉴로 구성한다. 검색과 선택 개체 도구는 필요한 때만 표시한다.
- 미리보기는 원문의 복사본만 렌더링하고 형식·켜짐을 세션에 보관한다. HTML은 스크립트·호스트 객체·웹 메시지·하위 프레임·양식 제출·다운로드를 차단하며 외부 페이지 이동은 사용자가 클릭한 HTTP/HTTPS 링크만 기본 브라우저로 연다.
- 미리보기 리소스는 문서 폴더와 하위 폴더의 허용된 이미지·CSS·글꼴만 중계한다. 원격 리소스, 상위 경로와 연결 파일/폴더를 차단한다. XML/SVG는 DTD와 외부 엔터티를 금지한다.
- 브라우저 런타임은 공식 Microsoft 배포본 전체를 체크섬 검증 후 앱에 포함한다. SDK와 런타임 약관·구성요소 고지를 보존하고 최초 미리보기에서 런타임 약관 동의를 받는다. Windows 10의 고정 런타임 권한은 앱 전용 런타임 폴더에만 설정하며 브라우저 샌드박스를 해제하지 않는다.

## 실행 복구와 설치 유지관리 (1.7.2 준비)

- PDFium은 1.7.0~1.7.1에서 앱 프로세스 안에 두었으나, 로딩 중 종료 신고에 따라 1.7.2부터 요청마다 별도 프로세스로 격리한다. 열기·검색·편집·저장 전 검증 모두 같은 경계를 사용하며 60초 제한·취소·부모 종료 시 자식 정리를 적용한다.
- 세션의 PDF 바이트를 먼저 복구하고 표시 준비는 탭 로드 후 수행한다. 복원 실패는 해당 탭에서 안내하고 명시적으로 재시도한다. 실패한 바이트·미저장 내용과 다른 문서를 보존한다.
- WebView2 컨트롤 생성도 오류 처리 범위 안에서 수행한다. 호환성을 위해 1.7.1의 CompositionControl을 표준 WPF WebView2로 변경한다. 실패한 브라우저의 Stop 등 네이티브 메서드를 오류 표시 경로에서 다시 호출하지 않는다. 새로 고침 시 컨트롤·환경을 다시 준비한다.
- 설치·제거는 실행 중 앱과 유지관리 중복을 이름 있는 mutex로 감지한다. 잠긴 패키지 파일·연결 경로를 변경 전에 검사한다. 일부 패키지 파일 삭제 실패 시 설치 식별자·제거 프로그램·등록을 보존해 재시도가 가능해야 한다.
- 설치 소유 파일 목록은 현재 payload와 `installer/legacy-files.txt`의 누적 목록을 합쳐 생성한다. 의존성 제거·이름 변경 때 이전 경로를 삭제하지 않는다. 제거는 이 목록의 파일과 빈 폴더만 대상으로 하며 사용자 파일·설정·작업 보관을 재귀 삭제하지 않는다.
- 예전 제거 실패의 식별자 없는 폴더는 기본 Programs 제품 폴더이며 모든 하위 경로가 소유 목록에 속하고 연결 경로가 없을 때만 복구 설치한다. 사용자 추가 파일이 남는 정상 제거는 `.wtext-retained` 소유 확인 파일을 남겨 재설치를 허용한다.
- 재설치는 파일별 압축과 NSIS `SetOverwrite ifdiff`로 배포 시각이 같은 파일의 압축 해제·쓰기를 생략한다. 실측 없이 설치 시간 개선 수치를 주장하지 않는다. 테스트의 Windows 실행과 Linux에서의 NSIS 컴파일을 구분한다.

## 대용량 텍스트 처리 (1.8.0 준비)

- 2026-11-03의 약 100MB 로그 로딩 종료 신고에 따라 기존 16 MiB 열기/저장 한도를 변경한다. 파일은 최대 256 MiB, 디코딩한 본문은 134,217,728자·2,000,000줄·한 줄 100,000자까지 읽는다. 창 내 본문 합계는 268,435,456자·4,000,000줄로 제한하며 다시 불러오는 동안의 이전 버퍼도 합산한다. 무제한 파일·가상 파일 편집을 보장하지 않는다.
- 16 MiB 이상 파일, 8,388,608자 이상 본문 또는 100,000줄 이상 문서는 대용량 모드로 처리한다. 문서 생성·복원·다시 불러오기·편집 중 증가에 같은 제한을 적용하고 설정 변경으로 해제하지 않는다. 편집 중 줄여도 다시 불러오기 전까지 보호 모드를 유지한다.
- 읽기·엄격한 디코딩·해시·AvalonEdit 버퍼/행 구성은 작업 스레드에서 청크로 처리한다. 읽기 성공 뒤에만 UI에 문서를 연결한다. 저장은 불변 스냅샷의 reader에서 인코딩·해시를 스트리밍하고 원본 교체 전 검증과 외부 변경 확인을 유지한다.
- 대용량 문서는 미리보기·미니맵·구문 강조·자동 줄바꿈·공백 표시·들여쓰기 감지·입력 후 전체 줄바꿈 분석·전체 검색 강조/개수·모두 바꾸기·동시 편집·자동 정렬을 제한한다. 일반 편집·저장·개별 바꾸기와 청크 기반 이전/다음 검색은 유지한다. 미리보기와 비교의 기존 한도는 본문 복사 전에 확인한다.
- 0.4.0의 미저장 버퍼 자동 보관과 1.5.0의 주기적 외부 변경 검사는 일반 문서에 유지한다. 대용량 문서는 본문 자동 보관과 주기적 디스크 해시/자동 갱신을 제외하고 화면에서 안내한다. 수정한 대용량 탭은 작업 이어하기 설정과 관계없이 창 종료 때 저장/버리기/취소를 확인한다. 자동 복구 제외를 알리지 않고 미저장 데이터를 버리지 않는다.
- 대용량 탭의 경로·표시 위치는 세션 형식 3에 기록한다. 재실행은 원본을 다시 읽으며, 원본을 읽지 못하면 안내하고 빈 편집 버퍼로 바꿔 원본을 덮어쓰지 않는다. 파일 없는 대용량 새 문서는 자동 복구하지 않으며 종료 때 저장 여부를 확인한다. 기존 형식 1/2는 계속 읽는다.
- 100 MiB 로그 청크 읽기/저장·인코딩 경계·취소·한도·검색·세션 검사를 유지한다. 비UI 버퍼 측정과 실제 Windows WPF 메모리·입력·화면·설치 검증을 구분한다. CI 중단은 계속 유지한다.

## 대용량 스크롤 보정 (1.8.1 준비)

- 1.8.0의 제한에 URL·이메일 자동 링크 검사를 추가한다. 대용량 파일은 자동 링크를 생성하지 않으며 작은 문서의 기존 표시와 설정을 유지한다.
- 대용량 휠 입력은 16ms 간격으로 한 목표 위치에 모아 반영한다. 이동량·고해상도 delta·시스템 줄/페이지 설정·문서 경계의 방향 전환을 보존하고 추가 관성 애니메이션이나 입력별 작업 큐를 만들지 않는다. 키보드/클릭/커서 이동·내용 변경·다른 스크롤·탭 숨김/닫기·설정 변경 때 대기 이동을 취소한다. Ctrl+휠 확대와 선택 드래그는 기존 경로를 사용한다.
- 대용량 스크롤바 드래그는 놓을 때 본문을 갱신하고 안내 툴팁·F1에 이 동작을 설명한다. 일반 문서는 연속 갱신을 유지한다. 작은 파일로 다시 불러오면 링크와 기본 스크롤을 복원한다.
- 스크롤 최적화는 본문·선택·커서·실행 취소를 바꾸지 않는다. 입력 누적과 경계는 Core에서, 실제 템플릿·휠/스크롤바 명령·본문 보존은 WPF에서 검사한다. Windows에서 측정하지 않은 개선률이나 프레임 시간을 주장하지 않는다.

## 줄 이동과 1.8.2 배포

- 텍스트 줄 이동은 Ctrl+G와 편집 메뉴로 제공한다. 1부터 시작하는 줄 또는 줄:열을 받고 원문 줄 번호/상태 표시줄의 열 기준을 따른다. 범위를 조용히 보정하지 않고 입력창에 안내하며 Esc·취소·X는 원래 커서와 선택을 보존한다.
- 대용량 줄 이동은 대상 줄의 인덱스/길이만 조회하며 전체 본문 문자열이나 행 배열을 생성하지 않는다. 원문·실행 취소·미저장 상태를 보존하고 이전 검색/휠 작업이 이동을 덮어쓰지 못하게 한다. PDF는 텍스트 줄 이동 대상에서 제외한다.
- 2026-11-03 사용자 확인·공개 요청에 따라 1.8.0~1.8.1의 미공개 대용량 개선과 줄 이동을 1.8.2로 함께 배포한다. 개선됐다는 사용자 확인과 자동 Windows WPF·화면·설치 검증을 구분하고 기존 CI 중단은 유지한다.
